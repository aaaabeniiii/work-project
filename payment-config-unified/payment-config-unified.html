2. 需求目的

後台「充值配置」歷經多次迭代，配置頁面分散、狀態定義不一致（二態／三態／兩欄組合並存，同一狀態在表單叫「停用」、列表顯示「關閉」），運營難以判斷「要配置某個東西該去哪一頁、配完前台長什麼樣」。

本次在不大幅改動架構的前提下進行統一，目標：

  1. 菜單即導覽：運營看菜單名稱與順序，即可理解各配置頁的定位與相互關係（渠道 → 方式 → 展示，充值與提款兩側對稱）。
  2. 狀態全站統一：所有層級只有「正常／維護／停用」三態，選什麼、列表就顯示什麼，前台呈現依同一套層級判斷。
  3. 展示來源單一化：前台看得到的東西，一定能在後台找到唯一的來源頁，不再有「配了吃展示配置、沒配吃後端預設」兩套並存的情況。
  4. 充提分流：第三方儲值與代付分成兩頁配置，運營新增金流廠商時不會再混淆。

5. 層級判斷原則

前台呈現依 渠道 → 方式（入口）→ 子通道 三層由上而下判斷，先判斷渠道、再判斷方式，兩層互不覆蓋、上層決定是否往下判斷：

  • 上層停用 → 不再判斷下層，該層以下前台整塊不顯示。
  • 上層維護 → 該層入口顯示維護，下層不再顯示（子通道不展開）。
  • 上層正常 → 才繼續往下判斷下一層。

6. 充值側規則

6.1 各層規則

第一層　渠道｜充值渠道管理

  • 清單由金流後台開通充值方式後同步回傳顯示，管理後台不可新增／刪除，可編輯狀態（三態）。
  • 渠道為最高層判斷：停用 → 該渠道下所有方式與子通道前台皆不顯示；維護 → 該渠道下所有方式入口顯示維護、子通道不顯示；正常 → 往下判斷方式層。
特別注意：目前所有第三方在線支付方式均掛在 onlinePayment 這一個渠道下。此渠道一旦停用，前台將沒有任何可用的充值方式；設為維護，則所有充值入口一律顯示維護。

第二層　方式（入口）｜在線支付商戶配置（展示由「在線支付展示配置」承接）

  • 新增流程：金流後台先配置好 → 於「在線支付商戶配置」選支付類型新增（其餘欄位操作人自填）→ 保存後列表顯示對應的渠道類型（如 326 - dragonpay_qrph，為金流後台既定對應）→ 再至「在線支付展示配置」選該渠道類型＋商戶、配置前台圖片，配置後前台才會展示。
  • 同一渠道類型可在「在線支付商戶配置」建立多筆（多家金流商承做同一種支付）；但「在線支付展示配置」中一個渠道類型只能建立一筆展示設定，且指定的商戶必須是同渠道類型底下的配置。
  • 前台一個渠道類型只會出現一個入口；實際承接訂單的商戶由展示設定的「顯示商戶」指定；未指定時，取當下該渠道類型底下狀態正常且排序最小的一筆商戶綁定。
  • 入口的狀態吃「在線支付商戶配置」中承接商戶那一筆的狀態；同渠道類型下其他商戶的狀態不影響入口呈現。「在線支付展示配置」本身無狀態、只負責展示。

第三層　子通道（金流 API 回傳）

  • 子通道清單由金流後台 API 回傳（如銀行類方式底下的 BDO、BOC 等），充值側不做子通道狀態判斷——第三方通常只回傳可用的子通道。
  • 子通道圖片於「在線支付展示配置」內設定。若先前 API 曾回傳且已設置過該子通道的圖片，後續 API 未回傳時，後台的子通道圖片設定區即不出現該子通道；之後再度回傳時，會自動帶回先前上傳過的圖片。
  • 若方式底下只有一個子通道，前台不展開子通道清單，點擊入口直接進入對應頁面。

7. 提款側規則

7.1 各層規則

第一層　渠道＝方式（入口）｜提款渠道管理

  • 出款渠道＝出款方式的前台入口（一筆記錄＝一個入口）；入口圖於本頁設定。
  • 清單來源同樣為金流後台開通後才顯示；管理後台可上傳入口圖、調整狀態（三態）。
  • 提款側渠道與方式為同一筆設定，狀態一次判斷（方式狀態隨渠道）。
  • 前台有哪些提款方式（Bank Card、eWallet 等），以及各入口顯示的入口圖與入口狀態，唯一來源即本頁。

第三方代付通道｜在線提款商戶配置

  • 原「在線支付配置」中的代付記錄全數移至本頁顯示；與「在線支付商戶配置」共用同一張底層表，以渠道類型（充值／代付）區分。
  • 本頁僅有代付：新增與編輯彈窗的支付類型下拉僅出現代付類選項。
  • 本頁狀態不參與前台顯示判斷，僅影響提款流程走自動出款或人工出款（商戶維護／停用時不走自動出款、回人工出款）。

第三層　子通道｜提款展示配置

  • 各入口方式底下的子通道（實際銀行／錢包清單，如 BDO、BPI、GCash、JuanCash），名稱、子通道圖示與狀態皆於本頁設定。
  • 前台提款頁的子通道層顯示內容（Bank Card 下有哪些銀行、eWallet 下有哪些類型錢包）唯一來源即本頁。
  • 子通道三態：停用 → 該子通道不顯示；維護 → 該子通道顯示維護；正常 → 正常顯示。

8. 其他既定原則

8.1 操作注意事項（不做系統判斷）

  • 同渠道類型多家金流商的切換：承接商戶於展示設定保存時即固定（指定與未指定皆同）；其後承接商戶維護／停用，系統不會自動輪替至其他商戶，需自行注意並手動切換「顯示商戶」。

8.2 用詞統一

  • 狀態文案全站統一為「正常／維護／停用」：編輯表單選了什麼，列表與篩選就顯示相同的文字，廢除「關閉」等別名。
  • 改動範圍說明：狀態文案統一（「關閉」→「停用」等）僅調整前端顯示文字，不改變既有資料的狀態值；渠道層由二態補為三態，屬新增「維護」狀態值，非文案調整。

8.3 技術依賴

  • 「在線支付商戶配置」與「在線提款商戶配置」共用同一張底層表，以渠道類型（充值／代付）過濾分頁。支付類型清單 API 須於列表階段即回傳渠道類型（而非保存後才回傳），兩頁的支付類型下拉才能各自過濾出儲值／代付選項。

「在線支付展示配置」含兩個頁籤：充值展示配置、分頁類型設定。分頁類型於「分頁類型設定」建立後，在充值展示配置的「分頁歸屬」皆可勾選；勾選後僅 WOWGame 生效。兩平台差異如下：

  • 當充值／提款所有渠道皆被停用時，前台將阻斷該功能的進入路徑，並跳出對應的語系提示彈窗。
