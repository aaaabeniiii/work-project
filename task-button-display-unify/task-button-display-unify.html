任務中心：按鈕顯示邏輯統一 規格書

一、目的

okbet、wowgame、123 三個平台共用同一套任務中心，但目前各平台的任務按鈕顯示邏輯不一致。本需求目的為統一三平台的按鈕顯示邏輯。

二、需求內容

  1. 判斷邏輯三平台統一。
  2. 各平台按鈕使用自身平台的文案與顏色（文案見第七章對應表，顏色依各平台設計稿，Figma 連結見 JIRA 附件）。
  3. 在不改動前後端現有回傳值與判斷值的前提下進行調整。
  4. 未登入時，點擊按鈕任務後觸發登入流程，登入後頁面位置在首頁。
  5. 其餘原有的跳轉方式及其他既有邏輯，一律不異動。
  6. 該任務類型未佈局展示在任務列表內的，則維持原有邏輯不調整展示。
    例如：Brand Daily Passcode 展示在優惠 banner，圣诞倒计时专属任务展示在特定頁面。
⚠ 備註：本規格書內所有按鈕文案均以 okbet 平台文案展示；wowgame / 123 對應文案見第七章。

說明：第四～六章所載之判斷邏輯均為現行既有邏輯，僅作對照說明用途；本次調整的是各判斷結果最終對應顯示的按鈕文案，實際實作方式由 RD 依現行架構評估。

三、按鈕顯示判斷流程圖

流程圖見流程圖檔案：「任務中心-按鈕顯示邏輯.png」（JIRA 附件）。

判斷順序：是否登入 → 任務是否已觸發（未觸發顯示「領取任務」）→ 第一層 任務完成狀態 → 第二層 任務參與要求（「未完成」為進入第二層的唯一來源）→ 第三層 任務條件（主條件＋子條件）。命中即停。

⚠ 與 RD 確認事項：
  1. 審核未通過（deliverStatus === 4）目前前端顯示「已過期」，本次調整為顯示「未通过」，請 RD 先確認此部分調整，是否可行，有沒有其他特殊情況會被影響到。
  2. 已過期：請 RD 確認目前有哪些情況會觸發顯示「已過期」，再討論此處做法。

五、第二層：任務參與要求（原邏輯說明）

後端於每個任務 item 回傳「勾選旗標＋未完成差額」，達成與否由後端計算，前端僅做判斷。由上而下逐項檢查，第一個未達成者決定按鈕（優先序：認證 > 充值 > 投注，依 RD 前端判斷說明）：

順序參與要求後端回傳欄位未達成判斷顯示按鈕
①完成 KYC 認證kycVerified（任務有勾此要求）
checkKycVerified（會員是否已通過）		kycVerified && !checkKycVerified去认证
②部分 KYC 認證
③累計充值totalRechAmountCheck（是否勾選）
unFinishRechAmount（未完成差額）		totalRechAmountCheck && unFinishRechAmount > 0去充值
④累計有效投注totalValidBetAmountCheck（是否勾選）
unFinishValidBetAmount（未完成差額）		totalValidBetAmountCheck && unFinishValidBetAmount > 0去投注

全部通過：上表各項未達成判斷皆不成立時，進入第三層判斷。

未勾選之要求：對應旗標欄位回傳 false，判斷式自然不成立，等同跳過。不論會員是否已完成任務條件，只要本層有任一要求未達成，即顯示本層導引按鈕。
⚠ 與 RD 確認事項：
  1. KYC 欄位：RD 文件僅有 kycVerified / checkKycVerified 一組欄位，但參與要求有「完成 KYC 認證」與「部分 KYC 認證」兩項——部分 KYC 是共用此組欄位、還是另有欄位？
  2. 參與要求全數通過時，後端是否另有回傳欄位，或僅以各項判斷皆不成立表示？
