OKF-2750 消息推送_新增自動消息 規格書

版本v1（2026-11-11）
需求單OKF-2750 消息推送_新增自動消息（App 未更新會員充值成功提醒）
關聯需求單OKF-2569 ok_bet充值改版（兩張單同版上線：UAT 11/19、生產 11/26）
影響範圍管理後台：公告管理 > 消息推送、公告管理 > 消息列表、日志管理 > 操作日志；後端：充值成功後的站內信發送

1. 需求目的

  1. 新增 App 未更新會員的提醒機制：會員使用尚未更新的 App 充值成功時，系統自動發送站內信到該會員的用戶消息中心，提醒會員更新 App。
  2. 此提醒以「自动消息」功能實作，放在「消息推送」新增的「自动消息」頁籤。自動消息做成可套用的模板（类型 → 触发时机 → 适用类型范围），日後有其他需要自動發送站內信的情境時，在同一功能下新增類型與觸發時機即可。本期只提供類型「充值」、觸發時機「充值成功」。
  3. 可新增多條自動消息設定。每條設定可指定適用類型範圍（初版／旧版(V2)／新版(V3)）、消息發送時間、每日發送上限、用戶範圍、消息展示方式、消息標題、消息內容與是否帶按鈕跳轉連結，並可編輯、開啟或關閉。
  4. 消息標題與消息內容可透過「国际化列表」設定各語系的內容。
  5. 自動消息的發送紀錄統一顯示在「消息列表」，消息類型新增「自动消息」。
  6. 自動消息設定的新增、編輯、開啟、關閉、刪除寫入「操作日志」。

2. 功能位置

公告管理 > 消息推送，在「活动消息」頁籤右側新增「自动消息」頁籤。頁籤內只有一個設定列表，不再分子頁籤。頁籤權限沿用「消息推送」頁面權限。

3.2 列表欄位

列表依建立順序由新到舊排序（最新建立的設定在最上面），分頁元件與「活动消息」頁籤相同。

欄位說明
类型該條設定的類型。本期只有「充值」。
触发时机該條設定的觸發時機。本期「充值」底下只有「充值成功」。
适用类型范围該條設定勾選的適用類型範圍，多個以半形逗號「,」分隔（例：初版,旧版(V2)），依 初版、旧版(V2)、新版(V3) 的順序顯示。表頭名稱後顯示「?」圖示，滑鼠移上顯示的說明與新增設定彈窗「适用类型范围」的說明相同：
  • 初版：最旧版 App，充值使用「充值配置」的设定
  • 旧版(V2)：尚未更新到最新版的 App，充值使用「充值配置（新）> 在线支付展示配置（新）> 充值展示配置」的设定
  • 新版(V3)：已更新到最新版的 App，充值使用「充值配置（新）> 在线支付展示配置（新）> 充值展示配置（新）」的设定
消息展示方式該條設定的消息展示方式。本期只有「用户消息中心」，即站內信。
消息标题該條設定新增時輸入的消息標題。超過欄寬以「…」截斷，滑鼠移上顯示完整內容。文字後固定顯示藍色「+」（开启、关闭狀態皆顯示），點擊開啟消息標題的「国际化列表」。
消息内容該條設定新增時輸入的消息內容。超過欄寬以「…」截斷，滑鼠移上顯示完整內容。文字後固定顯示藍色「+」（开启、关闭狀態皆顯示），點擊開啟消息內容的「国际化列表」。
按钮跳转链接按鈕跳轉連結選「是」時顯示填寫的連結，超過欄寬以「…」截斷，滑鼠移上顯示完整內容；選「否」時顯示「—」。
用户范围沿用「自定义消息」既有的用戶範圍功能，不異動。顯示該條設定選擇的選項：部分用户／所有用户／支付层级／在线用户。
指定对象沿用「自定义消息」列表「参数值」欄位的既有功能，欄位名稱改為「指定对象」。顯示選擇用戶範圍後所指定的對象：用戶範圍為「部分用户」時顯示填寫的會員帳號；為「支付层级」時顯示選擇的支付層級名稱（例：第二层）；為「所有用户」「在线用户」時顯示「—」。超過欄寬以「…」截斷，滑鼠移上顯示完整內容。
每日上限該條設定的每日發送上限。設定值為 0 時顯示「不限制」。
消息发送时间該條設定的消息發送時間，格式 YYYY/MM/DD ~ YYYY/MM/DD。
状态开启（綠色標籤）／关闭（灰色標籤）。
最后更新时间該條設定最後一次被新增、編輯、開啟或關閉的時間，格式 YYYY-MM-DD HH:mm:ss。
操作人名称最後一次對該條設定執行新增、編輯、開啟或關閉的後台帳號。
操作
  • 开启（狀態為关闭時顯示）：點擊後跳出確認視窗「确认开启吗？」，確認後狀態變為开启，立即生效；取消則不變更。
  • 关闭（狀態為开启時顯示）：點擊後跳出確認視窗「确认关闭吗？」，確認後狀態變為关闭，立即生效，之後不再依該條設定發送；取消則不變更。
  • 编辑：开启、关闭狀態皆可點擊。開啟「编辑设定」彈窗並帶入原設定值；「类型」「触发时机」不可修改，其餘欄位可修改。儲存後立即生效，之後的觸發依新設定判斷與發送；已發送的站內信不變動；狀態不變。
  • 删除：狀態為关闭時可點擊，跳出確認視窗「确认删除吗？」，確認後刪除該條設定，已發送的站內信與「消息列表」紀錄保留。狀態為开启時按鈕置灰不可點擊，須先關閉才能刪除。
  • 編輯「消息标题」「消息内容」只會修改新增設定時輸入的那一份內容；国际化列表內已設定的各語系內容不會跟著改，需另外由「+」修改。
  • 同一時間可開啟多條設定，不限制類型、觸發時機或適用類型範圍是否重複。

4.1 「?」說明圖示

  • 欄位的說明文字不直接顯示在畫面上，統一放在「?」圖示內。
  • 圖示位置：欄位名稱之後、冒號之前。
  • 滑鼠移到圖示上時，在圖示上方顯示深色底白字的提示框；滑鼠移開後消失。
  • 圖示為藍色圓形「?」（色值 #409EFF），樣式與「充值配置（新）> 提款渠道管理（新）」列表「层状态」表頭的「?」相同；提示框為深色底白字，樣式也與該處相同。
  • 有「?」的位置共五處：彈窗內的 适用类型范围、消息发送时间、每日发送上限、按钮跳转链接 四個欄位，以及列表「适用类型范围」表頭。五處的提示文字與顯示方式皆如介面示意。

4.2 區塊一：触发条件配置

欄位類型必填說明
类型下拉單選是選項：充值（本期唯一選項，預設選取）。類型決定下方「触发时机」與「适用类型范围」的選項。
触发时机下拉單選是選項依「类型」帶出。類型為「充值」時，選項：充值成功（本期唯一選項，預設選取）。
适用类型范围核取方塊（多選）是選項依「类型」帶出。類型為「充值」時，選項：初版、旧版(V2)、新版(V3)，至少勾選一項，預設皆不勾選。
「?」提示文字（三行）：
  • 初版：最旧版 App，充值使用「充值配置」的设定
  • 旧版(V2)：尚未更新到最新版的 App，充值使用「充值配置（新）> 在线支付展示配置（新）> 充值展示配置」的设定
  • 新版(V3)：已更新到最新版的 App，充值使用「充值配置（新）> 在线支付展示配置（新）> 充值展示配置（新）」的设定

4.3 區塊二：发送规则配置

欄位類型必填說明
消息发送时间日期區間是選擇開始日期與結束日期，格式 YYYY/MM/DD ~ YYYY/MM/DD。結束日期不得早於開始日期，開始日期與結束日期可為同一天。
「?」提示文字：只在这段日期内发送，从开始日 00:00:00 到结束日 23:59:59
每日发送上限數字輸入是只能輸入 0 以上的整數。0 表示不限制。
「?」提示文字（三行）：
  • 每位会员每天最多收到本条设定的封数
  • 填 0 表示不限制
  • 每天 00:00 重新计算
用户范围下拉單選是沿用「自定义消息」既有的用戶範圍功能，選項不異動：部分用户、所有用户、支付层级、在线用户。預設「所有用户」。
指定对象依用戶範圍變化是沿用「自定义消息」選擇用戶範圍後出現的附加欄位，既有功能不異動，只加上欄位名稱「指定对象」。
  • 用戶範圍為「部分用户」：顯示多行輸入框，提示文字「多个用户名用,分开」，上限 30000 字，沿用「自定义消息」部分用户名單的字數限制，輸入框下方顯示字數「目前字數/30000」。
  • 用戶範圍為「支付层级」：顯示下拉選單，提示文字「会员层级」，選項與「自定义消息」選擇支付层级時的「会员层级」下拉相同（例：默认层、第二层、第三层、第四层、第五层），單選。
  • 用戶範圍為「所有用户」「在线用户」：不顯示此欄位。

4.4 區塊三：消息内容配置

欄位類型必填說明
消息展示方式下拉單選是區塊內第一個欄位。選項只有「用户消息中心」，預設選取。不提供「app推送」。
消息标题單行輸入是上限 200 字，沿用「自定义消息」消息標題的字數限制，提示文字「200个字元以内」。此處輸入的是預設顯示的標題；其他語系的標題在設定新增後，由列表消息標題旁的「+」開啟「国际化列表」新增。
消息内容多行輸入是上限 1000 字，沿用「自定义消息」消息內容的字數限制，輸入框下方顯示字數「目前字數/1000」。此處輸入的是預設顯示的內容；其他語系的內容在設定新增後，由列表消息內容旁的「+」開啟「国际化列表」新增。
按钮跳转链接單選（是／否）是預設「否」。
  • 選「是」：選項下方顯示連結輸入框，提示文字「请输入链接」，必填。會員收到的站內信內顯示按鈕，點擊後前往填寫的連結（按鈕樣式與「活动消息」的站內信按鈕相同）。
  • 選「否」：不顯示連結輸入框，站內信內不顯示按鈕。由「是」改選「否」時，已輸入的連結清空。
「?」提示文字（兩行）：
  • 选「是」：站内信内显示按钮，会员点击后前往填写的链接
  • 选「否」：站内信内不显示按钮

5. 發送規則

5.1 類型「充值」、觸發時機「充值成功」

  • 充值訂單的狀態變為「成功」的當下觸發，符合條件後立即發送，不延遲。
  • 只有會員在前台送出的在線充值訂單會觸發。包含三方回調成功，以及後台在「充值纪录」對失敗訂單點「解锁通过」再點「通过」而變為成功的訂單。
  • 管理後台手動加值、投注站／代理替會員線下充值的訂單不屬於任何一個適用類型範圍，不觸發。

5.2 適用類型範圍的判斷

以該筆充值訂單下單時使用的充值下單 API 判斷它屬於哪一個適用類型範圍，對照如下。只看訂單下單時使用的 API，訂單成功時以下單當時的 API 為準。

後台選項（适用类型范围）對應的充值下單 API
初版初版充值下單 API
旧版(V2)V5 充值下單 API（搭配 V2 充值配置 API）
新版(V3)V6 充值下單 API（搭配 V3 充值配置 API）

5.3 消息發送時間

  • 觸發當下的平台時間（+08:00）落在開始日期 00:00:00 到結束日期 23:59:59 之間才發送。
  • 尚未到開始日期或已超過結束日期時不發送，也不在「消息列表」產生紀錄。
  • 「状态」與「消息发送时间」各自獨立：狀態為开启且觸發當下在消息發送時間內，兩者同時成立才發送。超過結束日期後，狀態欄不會自動變為关闭。

5.4 用戶範圍的判斷

用戶範圍沿用「自定义消息」既有功能，各選項的對象不異動。自動消息在觸發當下依下表判斷會員是否符合：

用戶範圍符合條件
部分用户觸發的會員帳號在該條設定「指定对象」填寫的名單內。
所有用户所有觸發的會員皆符合。
支付层级觸發當下，會員所屬的支付層級為該條設定「指定对象」選擇的層級。
在线用户觸發當下，會員為在線狀態。

5.5 每日發送上限

  • 以「每位會員、每條設定、每天」為單位計算：同一位會員一天內最多收到同一條設定的 N 封站內信。
  • N 為 0 時不限制，每次符合條件都發送。
  • 每天 00:00（平台時間 +08:00）重新計算。
  • 已達上限時該次不發送，也不在「消息列表」產生紀錄。
  • 編輯每日發送上限後，當天已發送的封數照算，以新的上限繼續判斷。

5.6 多條設定同時開啟

  • 一筆充值成功時，所有狀態為「开启」的設定各自獨立判斷，互不影響。
  • 同一筆充值符合多條設定時，每一條各發送一封站內信；每日發送上限也各自計算。

5.7 發送內容

  • 發送位置：會員的用戶消息中心（站內信）。不發送 app 推送。
  • 標題、內容：會員使用的語系在該條設定的国际化列表有設定時，顯示該語系的標題、內容；沒有設定時，顯示新增設定時輸入的消息標題、消息內容。標題與內容各自判斷。
  • 該條設定的按鈕跳轉連結為「是」時，站內信內顯示按鈕並連到設定的連結；為「否」時不顯示按鈕。
