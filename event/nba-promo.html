後台規格前台示意互動原型

一、需求目的

  • 在「活动配置（新）」新增一個活動模板「体育活动」，走既有的六步驟配置流程（活动模板设置 → 活动图片 → 参与对象与名单 → 活动条件 → 风控条件 → 提交预览）。
  • 步驟 1、2、3、5、6 沿用模板共用欄位，只在步驟 1 加「展示时间」「未登入是否可见」、步驟 3 加「KYC 验证」。
  • 步驟 4「活动条件」為本模板專屬：奖励配置（每日）（含各項次的適用遊戲範圍）、通用派奖配置。
  • 獎勵為「体育投注券」（沿用 积分商城 › 优惠券管理 既有模板），達標後由會員在前台手動領取、系統直接派券，不走派奖审核。
  • 每日任務達標判斷以會員當日累計數據與各項次「需求」比較，達成條件（投注额／充值）各自獨立計算、各自獨立領取。
  • 活动配置（新） › 活动报表 需支援本模板的明細與統計欄位。

二、配置流程總覽

  • 在 活动列表 點「新增活动」，步驟 1 的「活动类型」下拉多一個選項「体育活动」；選定後步驟 2～6 依本模板呈現。
  • 每一步點「下一步」時校驗該步必填（與現有模板相同）；步驟 6 點「提交」寫入。
  • 「退出编辑」跳「确定退出编辑?未保存的修改将丢失」確認框。
  • 活動開啟中可再進入編輯，修改後立即生效。
  • 活动列表 的操作與現有相同：
    • 编辑：開啟同一套六步精靈（编辑活动），帶入原設定；活动类型 反灰不可更換（與現有相同）。
    • 删除：状态＝开启 的活動不可刪除（删除 反灰）；关闭 的可刪，刪除前跳「确定删除该活动?」確認。
    • 开启／关闭：切換活動狀態。

项次系統編號是
  • 依新增順序自動編號 1、2、3…；刪除後重新編號。
  • 每一列只要存在就整列必填，項次前都帶 *。
  • 至少保留一個項次：只剩一列時該列「删除」反灰不可點；項次總數即本活動每日獎勵數量，上限 10，達 10 筆時「新增」按鈕反灰。
达成条件下拉單選是
  • 選項：投注额／充值。
  • 投注额＝會員當日在適用遊戲範圍（在「需求」欄上方設定）內的有效投注額。
  • 充值＝會員當日充值成功金額累計。
  • 同一筆投注可同時計入多個投注额項次（各項次依自己的適用遊戲範圍判斷）。用体育投注券下的注單不計有效投注，所以不計入。同一達成條件可設多筆。
需求下拉＋數字輸入（上下排）是
  • 达成条件＝投注额時，欄位上方先有一個下拉（適用遊戲範圍）：指定游戏／指定体育赛事，預設「指定游戏」；下方才是需求數字。指定游戏 本期固定全選＝请选择游戏 彈窗清單內的全部（含自有体育與所有廠商遊戲）。达成条件＝充值時只有需求數字。
  • 需求：只能輸入數字，小數點、負號、字母打不進去（輸入即被擋），填 0 視為未填。項次之間的達成條件、適用遊戲範圍、需求可以完全相同，不限制。
展開區列下方展開區依選項
  • 依適用遊戲範圍的值，在該列正下方接一個淺灰展開區，內容從达成条件欄對齊開始（项次欄留白）：
    • 指定游戏：展開「选择游戏」按鈕＋「已选择 全部 游戏」摘要。按鈕與彈窗沿用 预约活动 步驟 4「适用游戏范围」的「请选择游戏」彈窗（全选／廠商／遊戲勾選）。本期先不開放指定選遊戲：彈窗固定全選、所有選項反灰不可取消，摘要固定「已选择 全部 游戏」。
    • 指定体育赛事：展開 适用类型（本期固定「篮球」反灰打勾）與 可参与体育投注赛事（全部／指定，預設全部）；選「指定」時再接「选择联赛」「选择赛事」兩顆按鈕與已選清單。
  • 切換範圍選項時清空原本的選擇。
可参与体育投注赛事單選＋提示指定体育赛事時必填
  • 單選：全部／指定，預設「全部」。只決定該項次「投注额」的統計範圍，不影響前台 PICK YOUR GAME 列的賽事，也不限制券的使用賽事。
  • 全部：篮球所有賽事的投注皆計入。
  • 指定：計入範圍＝所選聯賽底下全部賽事（含活動期間內新增的賽事）＋ 所選賽事，取聯集；保存時聯賽與賽事至少擇一有選擇，否則擋下提示「请至少选择一个联赛或赛事」。
  • 欄位名稱後加「?」圖示，滑入顯示提示文案：
    • 全部：篮球所有赛事的投注皆计入
    • 指定：只计入所选联赛底下的全部赛事 ＋ 所选赛事，两者取联集
    • 联赛与赛事可同时选择，互不影响；所选联赛下的全部赛事与单独勾选的赛事都会计入，重复的只算一次
    • 指定时联赛、赛事至少择一选择
选择联赛 彈窗按鈕＋彈窗—
  • 直接套用 游戏管理 › 联赛管理 頁面（篩選、欄位都一樣：联赛ID、名、联赛类别代码、联赛类型、开始/结束时间——上下兩行，第一行開始時間、第二行結束時間），每列前面多一個勾選框。
  • 固定籃球，所以不顯示球類頁籤；頁籤只剩「普通联赛／冠军联赛」，兩個頁籤的勾選合併計算。
  • 清單用分頁（與後台相同：每頁筆數可選 10／20／30／40／50／100，預設 20；可跳頁），不用捲軸；跨頁、跨頁籤的勾選都保留，右上角「已选 n 个」統計全部已勾選。
  • 不限制選擇數量。
  • 兩個彈窗各自獨立、互不過濾；計算時同一場賽事被聯賽與賽事同時涵蓋只計一次。

  1. 整體判斷
    • 活动状态＝关闭 → 所有入口不顯示；直接開網址 → 導回首頁。
    • 活动状态＝开启 → 進入入口處判斷。
  2. 入口處判斷（入口＝首頁浮窗、Rewards › Promotion 活動卡片）
    • 展示时间
      • 不在展示时间內 → 所有入口不顯示；直接開網址 → 導回首頁。
      • 在展示时间內 → 入口可見（浮窗、活動卡片依各自開關顯示，直接開網址可進活動頁），再進下一項判斷。
    • 活动图片 › 首页浮窗设置／活动列表设置
      • 关闭 → 對應的入口不顯示（開關只管自己那個入口）；直接開網址 → 照常進入活動頁。
      • 开启 → 對應的入口顯示，再進下一項判斷。
    • 登入狀態
      • 未登入，且「未登入是否可见」＝否 → 入口不顯示；直接開網址 → 導向登入頁。
      • 未登入，且「未登入是否可见」＝是 → 顯示入口，點擊進入活動頁（頁內行為依下一層）。
      • 已登入 → 顯示入口，點擊進入活動頁。
  3. 進入頁面後判斷
    • 未登入，且「未登入是否可见」＝是 → 頁面純展示（無進度、無領取按鈕），點擊頁內任一按鈕 → 導向登入頁。
    • 已登入，在展示时间內但不在活动时间內 → 任務卡顯示「未开始」或「已结束」，領取按鈕不可點。
    • 已登入，在活动时间內 → 依各項次顯示任務卡狀態：
      • 當日累計值 < 需求 → 顯示進度（當日累計值 / 需求），按鈕不可點。
      • 當日累計值 ≥ 需求，且當日未領 → 按鈕顯示「可领取」。
      • 當日已領 → 按鈕顯示「已领取」，不可再點。
  4. 點擊「可领取」（只檢查 KYC）
    • 會員 KYC 狀態不在勾選範圍 → 不派券，提示「请先完成 KYC 验证」，按鈕維持「可领取」。
    • 通過 → 派發該項次設定的体育投注券，寫入优惠券记录（來源：体育活动）與活动报表，按鈕轉為「已领取」。

  • 報表時間欄擬改為「达标时间」「领取时间」。
確認不採「達標即派券、不用點領取」；若營運要那種，發放方式改自動派發、KYC 改在達標時判斷、IP 限制拿掉，是另一種設計。
