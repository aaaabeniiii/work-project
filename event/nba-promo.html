後台規格前台示意

一、需求目的

  • 在「活动配置（新）」新增一個活動模板「篮球活动」，走既有的六步驟配置流程（活动模板设置 → 活动图片 → 参与对象与名单 → 活动条件 → 风控条件 → 提交预览）。
  • 步驟 1、2、3、5、6 沿用模板共用欄位，只在步驟 1 加「展示时间」「未登入是否可见」、步驟 3 加「KYC 验证」。
  • 步驟 4「活动条件」為本模板專屬：奖励配置（每日）、游戏配置、通用派奖配置。
  • 獎勵為「体育投注券」（沿用 积分商城 › 优惠券管理 既有模板），達標後由會員在前台手動領取、系統直接派券，不走派奖审核。
  • 每日任務達標判斷以會員當日累計數據與各項次「需求」比較，三種達成條件（总投注额／充值／体育投注额）各自獨立計算、各自獨立領取。
  • 活动配置（新） › 活动报表 需支援本模板的明細與統計欄位。

二、配置流程總覽

在 活动列表 點「新增活动」，步驟 1 的「活动类型」下拉多一個選項「篮球活动」；選定後步驟 2～6 依本模板呈現。每一步「下一步」時校驗該步必填（與現有模板相同），步驟 6 點「提交」寫入；「退出编辑」跳「确定退出编辑?未保存的修改将丢失」確認框。活動開啟中可再進入編輯，修改後立即生效。
步驟名稱與現有模板本模板的內容
1活动模板设置共用＋新增活动类型（新增「篮球活动」）、活动名称、币种、状态、活动时间；新增 展示时间、未登入是否可见。
2活动图片共用首页浮窗设置（PC／H5 图片、排序）、活动列表设置（PC／H5 图片、排序）、备注。與現有相同。
3参与对象与名单共用＋新增充值层级、指定代理、新会员限制、会员等级、用户标签、黑名单；新增 KYC 验证。
4活动条件本模板專屬奖励配置（每日）、游戏配置、通用派奖配置。
5风控条件共用同IP／同手机号／同姓名／同email 检测、自动拒绝。
6提交预览共用依步驟列出所有欄位摘要，確認後提交。

達標與領取規則（固定邏輯，不開放設定）

  • 統計週期：每日 00:00:00～23:59:59（UTC+8），以注單投注時間、充值成功時間歸日；次日 00:00 全部項次進度歸零。
  • 達標判斷：每個項次都拿「會員當日累計值」與自己的需求比較，累計值 ≥ 需求即達標；累計值不會因某個項次達標或領取而扣除，各項次獨立、無順序限制。
    例一：總投注額設 100、體育投注額設 100，會員下注體育 100 → 當日總投注額 100、體育投注額 100，兩個項次同時達成。
    例二：體育投注額設兩筆，需求 50 與 100，會員當日體育投注累計 80 → 只有需求 50 的項次達成；累計到 120 → 兩筆都達成（不是 50＋100＝150 才達成第二筆）。
  • 進度更新：依注單與充值紀錄定時更新（與其他專項活動相同頻率）；前台顯示「可領取」即代表已達標，點擊即派券。
  • 領取：每人每項次每日一次；點擊後即派券，優惠券記錄來源標記「篮球活动」，有效期自派發起算。領取中鎖定該項次，防重複提交；派券失敗（券模板已刪除、優惠券系統開關關閉）回傳錯誤、該項次保持可領取。
  • 每日重置：次日 00:00 所有項次進度歸零、領取狀態重置；前一日達標但未領取的項次不保留、不可補領。
  • 體育投注額計算只取投注狀態為已確認的注單；取消／作廢的注單自累計值扣回，若扣回後低於已領取項次需求，不收回已派的券。

十一、前台判斷

適用 PC／H5／APP 三個渠道；入口為首頁浮窗、Rewards › Promotion 活動卡片（各自依活动图片的開關顯示）、直接開啟活動頁網址。
  1. 整體判斷
    • 活动状态＝关闭 → 所有入口不顯示；直接開網址 → 導回首頁。
    • 活动状态＝开启 → 進入入口處判斷。
  2. 入口處判斷（入口＝首頁浮窗、Rewards › Promotion 活動卡片）
    • 展示时间
      • 不在展示时间內 → 所有入口不顯示；直接開網址 → 導回首頁。
      • 在展示时间內 → 入口可見（浮窗、活動卡片依各自開關顯示，直接開網址可進活動頁），再進下一項判斷。
    • 活动图片 › 首页浮窗设置／活动列表设置
      • 关闭 → 對應的入口不顯示（開關只管自己那個入口）；直接開網址 → 照常進入活動頁。
      • 开启 → 對應的入口顯示，再進下一項判斷。
    • 登入狀態
      • 未登入，且「未登入是否可见」＝否 → 入口不顯示；直接開網址 → 導向登入頁。
      • 未登入，且「未登入是否可见」＝是 → 顯示入口，點擊進入活動頁（頁內行為依下一層）。
      • 已登入 → 顯示入口，點擊進入活動頁。
  3. 進入頁面後判斷
    • 未登入，且「未登入是否可见」＝是 → 頁面純展示（無進度、無領取按鈕），點擊頁內任一按鈕 → 導向登入頁。
    • 已登入，在展示时间內但不在活动时间內 → 任務卡顯示「未开始」或「已结束」，領取按鈕不可點。
    • 已登入，在活动时间內 → 依各項次顯示任務卡狀態：
      • 當日累計值 < 需求 → 顯示進度（當日累計值 / 需求），按鈕不可點。
      • 當日累計值 ≥ 需求，且當日未領 → 按鈕顯示「可领取」。
      • 當日已領 → 按鈕顯示「已领取」，不可再點。
  4. 點擊「可领取」（只檢查 KYC）
    • 會員 KYC 狀態不在勾選範圍 → 不派券，提示「请先完成 KYC 验证」，按鈕維持「可领取」。
    • 通過 → 派發該項次設定的体育投注券，寫入优惠券记录（來源：篮球活动）與活动报表，按鈕轉為「已领取」。
  5. 每日重置：次日 00:00（UTC+8）所有項次進度歸零、按鈕回到不可點；前一日未領取的項次不可補領。

  • 設計稿目前沒有這塊，要不要加、放哪（HOW TO PLAY 下方或 Rules 彈窗）。

  • 活動文件只畫了 LOCKED、USE NOW。
  • 券已使用／已過期時，按鈕顯示 USED／EXPIRED（不可點）還是不顯示按鈕、只留右側狀態文字。
3PICK YOUR GAME 的說明行
  • 活動文件示意圖上有「Example fixtures*Times are for illustration」（示範賽事、時間僅供參考）。
  • 我們直接接推薦賽事，顯示的是真實賽事，這行要不要拿掉。
4券卡與籃球卡的連動方向
  • 點籃球卡切換券卡已確定。
  • 券卡本身能不能左右滑動、滑動時上方籃球卡要不要同步切換，待設計確認。
5不符合風控條件時的呈現
  • 後台步驟 5 的風險檢測（同IP／同手机号／同姓名／同email）與自动拒绝開啟時，會員被判定不符合：
  • 前台是先擋在領取前（按鈕不可點）還是點領取後才擋。
  • 要不要提示、提示文字是什麼（不能透露是哪一項風控）。
  • 該筆在 活动数据统计 的「状态」顯示什麼（已拒绝？）。
6不符合參與條件時能不能看到活動頁
  • 步驟 3 的參與條件（充值层级、指定代理、新会员限制、会员等级、用户标签、黑名单、KYC 验证）任一不符合的會員：
  • 入口（首頁浮窗、Rewards › Promotion 卡片）顯不顯示。
  • 活動頁能不能開；能開的話任務進度要不要顯示、按鈕怎麼呈現。
  • 要不要提示、提示文字。
  • KYC 目前定為：頁可開、進度照顯、點領取才提示並導 KYC 頁；其他條件是否比照。
7PICK YOUR GAME 推薦賽事裡沒有 NBA 時
  • 目前預設只顯示 NBA；推薦賽事是營運另外設的，當天可能沒有 NBA。
  • 沒有 NBA 時要不要改顯示其他籃球賽事。
  • 完全沒有可顯示的賽事時，區塊顯示空狀態還是整塊隱藏。
8未登入可見＝是時頁面怎麼顯示
  • 任務卡是不是全部 Locked、計數顯示 0 / M。
  • 券卡與按鈕顯示什麼。
9進頁預設選中哪張卡
  • 排序第一張，還是第一張「可領取」的卡。
10「投籃成功回饋」的定義
